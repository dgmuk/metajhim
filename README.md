# MetaJhim 100

Дневник Дмитрия Мухина: 16-недельный цикл жима 100 кг, план и факт, графики прогресса, календарь ПКТ. Основной интерфейс находится в `index.html`: Vanilla JS, CSS и SVG, без внешних библиотек и сборки. Для установки PWA используются `manifest.webmanifest`, `sw.js` и папка `icons/`. Кодировка — UTF-8; настройки для редакторов в `.editorconfig`.

## Запуск

Верхняя шапка свёрнута по умолчанию: нажатие на название MetaJhim раскрывает описание, установку приложения, JSON-отчёт, импорт и экспорт. Настройки цели и даты соревнований, выбор недели, четыре итоговых показателя и поля факта объединены в один свёрнутый блок «Показатели и настройки недели». Синхронизация и переключение недели в дневнике доступны снаружи этих блоков. Сворачивание не меняет данные; при перезагрузке оба блока снова закрыты.

Блоки ПКТ, графиков и таблицы 16 недель свёрнуты при каждом открытии страницы. ПКТ и таблица цикла раскрываются по нажатию на заголовок; заголовки графиков открывают крупный просмотр; доступно управление клавишами Enter / Space. Состояние раскрытия не синхронизируется и не меняет данные дневника. Во время редактирования и фоновой синхронизации раскрытые блоки остаются открытыми.

Откройте `index.html` в браузере или выполните в папке:

```sh
python -m http.server 8000
```

Откройте `http://localhost:8000`. Clipboard API доступен на HTTPS / localhost; если копирование запрещено, приложение покажет выделенный текст для ручного копирования.

## Облачная синхронизация Supabase

Клиент в `cloud-sync.js`, подключение настроено на проект `vybgmqjilhfsythiutnw`. В исходнике находится только публичный Publishable key. Пароль пользователя вводится в форме входа и не записывается в исходники, дневник и JSON-архив. Сессия хранится отдельно в `metajhim_cloud_session_v1`; выход удаляет сессию, сохраняя локальный дневник.

Однократная настройка в Supabase:

1. **Authentication → Users → Add user → Create new user**: создайте одного пользователя с вашим email и отдельным паролем для дневника. Включите подтверждение email при создании (Auto Confirm), если доступно. Пароль не присылайте разработчику.
2. **SQL Editor → New query**: вставьте весь `supabase/setup.sql` и нажмите **Run**. Скрипт требует ровно одного пользователя в новом проекте, закрепляет его как единственного владельца, создаёт таблицу `diary_state` и включает Row Level Security. Анонимный доступ закрыт. Даже другие зарегистрированные пользователи проекта не получают доступ к этой таблице. Существующие данные скрипт не удаляет.
3. В настройках Authentication отключите регистрацию новых пользователей (Allow new users to sign up) — приложению нужен только созданный аккаунт. В приложении формы регистрации нет.
4. Сначала на **телефоне, где заполнен дневник**, нажмите «Войти и синхронизировать». Войдите с созданными email и паролем. При пустой базе этот дневник загрузится в облако. На компьютере войдите в тот же аккаунт; при первом выборе нажмите «Использовать облачный дневник». Если облако ранее заполнено менее полной версией, сначала на телефоне выберите «Загрузить дневник с этого устройства».

Синхронизируются план, тренировки, подходы, комментарии, метрики и добавки. Сохранение отправляется с задержкой 1.2 секунды, новые облачные записи проверяются раз в 20 секунд, при возвращении на страницу и восстановлении сети. В режиме офлайн изменения остаются в localStorage и отправляются после подключения.

Кнопка **«Синхронизировать»** дожидается уже выполняющегося запроса, получает актуальные данные и открывает обновлённую неделю. Если нужен вход, открывает форму. При ручной синхронизации облачные значения имеют приоритет в конфликтующих полях, независимые локальные изменения сохраняются. Перед заменой сохраняется резервная копия, доступная через «Аккаунт → Копия до синхронизации» (обычный JSON-архив для восстановления). Автоматическая синхронизация продолжает запрашивать выбор при конфликте. Первое подключение вручную также предпочитает существующую облачную версию; если облако пустое, загружает локальную.

Обновления плана передают `planUpdate` с номером недели и уникальной меткой: другое устройство открывает эту неделю, получив новый план. При ручном обновлении старых планов без метки определяется изменённая неделя в `customPlan`. Ссылка `?sync=1` запускает ручную синхронизацию сразу после открытия. Скрипт облака имеет версию в URL и запрашивается по сети с офлайн-резервом, чтобы старая версия service worker не мешала исправлениям.

Для защиты от перезаписи используются ревизии строки и трёхстороннее объединение с последней известной облачной версией. Независимые поля объединяются. Конфликт в одном поле или массиве подходов требует выбора; автоматической замены нет. При первом подключении отличающегося дневника тоже нужен выбор. Обе версии сохраняются в `metajhim_cloud_backup_v1` и доступны кнопкой «Скачать обе версии». Принудительные изменения облака в обход ревизий не используются. SQL необходимо выполнить в своём аккаунте Supabase: Publishable key не даёт права создавать таблицы или пользователей.

Браузерные тесты проверяют сценарии двух устройств с имитированным API: вход, первый выбор, загрузку изменений, объединение, конфликты, офлайн-очередь, восстановление сессии и выход. Проверка реального проекта возможна после выполнения SQL и создания аккаунта.

## Локальное состояние и перенос

Карточки упражнений при каждом новом открытии страницы свёрнуты. Раскрывайте нужную карточку нажатием на название. Во время работы она остаётся открытой при добавлении и удалении подходов; состояние раскрытия не записывается в дневник.

Основной ключ localStorage: **`metajhim_dmitry_v2`**. Если он отсутствует, приложение читает данные `metajhim_dmitry_v4` из присланной версии. Следующие изменения сохраняются в `v2`; `v4` не удаляется. При наличии обоих приоритет имеет `v2`.

Старое поле `shoulder` мигрирует в `shoulderLeft`; `shoulderRight` остаётся пустым до ввода. Нулевые значения RIR и дискомфорта сохраняются; пустые поля не превращаются в нули на графиках. При внесении факта сохраняется снимок плана недели. Ошибка чтения сохранения не приводит к его автоматической перезаписи.

Кнопка «Скачать JSON-архив» экспортирует весь дневник, включая `suppChecks`. Для переноса вставьте архив в окно импорта и выберите «Восстановить полный JSON-архив». Эта отдельная операция заменяет все данные после подтверждения. При повреждённом сохранении экспортируется его исходное содержимое для восстановления.

LocalStorage зависит от браузера и адреса сайта. Перед переносом с локального файла на GitHub Pages скачайте архив, затем восстановите на новом адресе. Вводимые в браузере факты автоматически на GitHub не отправляются.

## Календарь ПКТ

Дата последнего укола зафиксирована: 18.10.2026. Даты и дозировки показаны как **пользовательский график из ТЗ**, а не назначение приложения. 21 день — календарный ориентир, а не утверждение о полном выведении препарата. В интерфейсе есть ссылка на [информацию о кломифене](https://medlineplus.gov/druginfo/meds/a682704.html).

График: 08–14.11 и 15–21.11 — 50 мг/сутки, 22–28.11 и 29.11–05.12 — 25 мг/сутки. До 08.11 отображается обратный отсчёт, с 06.12 — завершение графика. Календарь и таймер соревнований используют текущую дату Москвы и обновляются при наступлении нового дня.

Блок добавок полностью удалён из интерфейса. Прежние отметки `state.suppChecks` сохраняются для совместимости с архивами и облаком; их автоматическое удаление не выполняется.

## Крупный просмотр графиков

Нажатие на заголовок «Ваш прогресс · жим 100 кг» или «Вес и самочувствие» открывает график на весь размер окна. Работают выбор недель, переключение веса / плеча и легенда. Масштаб регулируется от 100 до 200%; широкая шкала прокручивается горизонтально, особенно на телефоне. Кнопка «Закрыть» или Escape возвращает карточку на исходное место и восстанавливает позицию страницы. В просмотр переносится существующая карточка — копий полей и SVG с одинаковыми идентификаторами нет.

## JSON для тренера

### Замена недели с пустым фактом

Обычный патч по-прежнему не очищает историю. Для намеренной замены недели добавьте `resetWeeks: [2]` и полный план этой недели в `plan` / `customPlan`. Либо отметьте в окне импорта «Заменить план и очистить подходы недели» и выберите номер. Предпросмотр явно перечисляет очистку; без нажатия «Применить патч» ничего не меняется.

При замене удаляются только в выбранных неделях: `workouts` (подходы и комментарии упражнений), `planSnapshot`, `d1_fact` / `d2_fact` / `d3_fact`, отметки завершения дней, `reps100` и `rir`. Вес, плечи, заметки недели, добавки и другие недели сохраняются. Полная копия до замены записывается в `metajhim_plan_reset_backup_v1`; её можно скачать из окна импорта и восстановить как обычный JSON-архив. Если резервную копию или новый дневник не удалось сохранить, замена не применяется.

План недели №2 из присланного JSON находится в `plans/week-2.json`: только эта неделя, без изменения недель 1 и 3–16 и без переноса полей анализов. Ссылка `https://dgmuk.github.io/metajhim/?plan=week-2` загружает его в предпросмотр, но не применяет автоматически. После применения работает обычная облачная синхронизация.

Копируется текстовая сводка выбранной тренировочной недели и одна компактная строка JSON (`metajhim.weekly-report.v1`). Включены план и факт трёх дней, вес, лучший подход 100 кг, RIR, оба плеча, анализы, календарь ПКТ и отметки добавок за соответствующую тренировочную неделю. Лучший подход — число повторов в одном подходе, а не сумма кластеров.

Пример ответа тренера:

```json
{
  "schema": "metajhim.coach-patch.v1",
  "settings": { "targetReps": 27, "compDate": "2027-02-21" },
  "plan": [
    { "w": 2, "d1_main": "107.5 кг: 4×6 (RIR 2)" },
    { "w": 3, "target100": 17 }
  ]
}
```

Вставьте только JSON → «Проверить патч» → прочитайте изменения → «Применить патч». Защищены текущая неделя по календарю цикла и все недели до последней с внесённым фактом. Начало цикла — 19.10.2026. Выбор недели для просмотра не меняет границу защиты. Защищённые недели пропускаются, остальные обновляются частично. Любая ошибка структуры отменяет весь патч; ошибка записи localStorage оставляет активный план без изменений.

Поля недели: `w`, `phase`, `isDeload`, `target100`, `d1_main`, `d1_acc`, `d2_all`, `d3_main`, `d3_acc`. `w`: целое 1–16; `target100`: целое 1–100. Настройки: `targetReps` (24 / 26 / 27 / 29) и `compDate` (YYYY-MM-DD или пустая строка). Можно использовать `customPlan` вместо `plan`, в том числе из старого архива. История `weeks`, отметки `suppChecks`, дата последнего укола и другие личные данные при патче не заменяются. Для их переноса используется полное восстановление архива.

## Дневник по подходам

В дневнике выбираются неделя и один из трёх дней (ПН / СР / ПТ). Каждое упражнение имеет отдельную карточку: план, вес / повторения / RIR каждого подхода, комментарий и добавление подхода. Для статических удержаний вместо повторений вводятся секунды. Пустые поля сохраняются как `null`, нулевой RIR — как `0`. Прежние записи `d1_fact` / `d2_fact` / `d3_fact` доступны под «Прежняя запись дня».

Факты хранятся в `state.weeks[week].workouts.d1` (аналогично `d2`, `d3`):

```json
{
  "date": "2026-10-19",
  "exercises": [
    {
      "id": "d1-main",
      "name": "Соревновательный жим лёжа",
      "prescription": "100 кг × 15 + 3×5",
      "unit": "reps",
      "sets": [{ "weight": 100, "reps": 15, "rir": 2 }],
      "comment": "Техника ровная"
    }
  ]
}
```

Эта структура входит в JSON-отчёт и полный архив; восстановление архива снова строит из неё карточки дневника. Лучший подход жима на 100 кг учитывается в сводке и графике, без суммирования повторов разных подходов.

План поддерживает дополнительное поле `days`: объект с массивами упражнений `d1`, `d2`, `d3`. У каждого упражнения обязательны `id`, `name`, `prescription`, `setCount` (1–30), `unit` (`reps` / `seconds`). `id` стабилен между редакциями плана. JSON-отчёт и новый архив содержат и прежние строковые поля, и `days`. Патч тренера может передать `days` для будущей недели. Исторические упражнения и подходы сохраняются в снимке плана и факте.

## Установка на смартфон (PWA)

Если Chrome ошибочно сообщает «Уже установлено», приложение не открывается и его нет в списке Android, доступен отдельный путь повторной установки: `https://dgmuk.github.io/metajhim/?install=repair`. Он подключает `manifest-repair.webmanifest` с отдельным стабильным `id`; стартовый адрес сохраняет `?install=repair`. Обычный манифест и идентичность существующих установок не меняются. Это обход возможной некорректной записи Chrome, а не подтверждение устранения системного сбоя: результат нужно проверить на самом телефоне. [Как Chrome определяет идентичность PWA](https://developer.chrome.com/docs/capabilities/pwa-manifest-id).

Режим повторной установки не очищает localStorage и использует тот же сайт и ключ дневника. Согласие в системном диалоге само по себе не считается завершением установки: кнопка скрывается после события `appinstalled` или запуска в standalone-режиме.

Откройте `https://dgmuk.github.io/metajhim/` на телефоне после публикации новой версии. Нажмите «Установить приложение». В Chrome на Android появится системное предложение установки, когда браузер сочтёт приложение доступным для установки. Также можно воспользоваться меню Chrome → «Установить приложение». На iPhone: Safari → «Поделиться» → «На экран Домой»; включите «Открывать как веб-приложение», если этот переключатель доступен.

`display: standalone` в манифесте обеспечивает запуск с отдельной иконки без панели браузера. Иконки PNG: 192 и 512 пикселей, включая maskable-вариант; Apple Touch Icon — 180 пикселей. Стабильный идентификатор, стартовый адрес и область действия указаны относительно папки приложения, поэтому поддерживается путь `/metajhim/`. [Требования к устанавливаемым PWA — MDN](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable).

После первой успешной загрузки service worker сохраняет оболочку приложения для работы без интернета. Подходы сохраняются локально обычным способом. При наличии сети HTML запрашивается заново, чтобы изменения не застревали в старом кэше. Открытый дневник не перезагружается автоматически. При обновлении `sw.js` меняйте версию `CACHE_NAME`; старый кэш только этого приложения удаляется после активации нового worker. LocalStorage не очищается.

Если ранее был создан обычный ярлык сайта, сначала установите PWA, затем удалите старый ярлык. Перед удалением установленного приложения скачайте JSON-архив: некоторые системы могут удалить его локальное хранилище. Данные не синхронизируются автоматически между браузерами и устройствами; на iOS установленное приложение может использовать отдельное хранилище, поэтому при необходимости перенесите дневник через JSON-архив.

Для установки и офлайн-режима нужен HTTPS (на GitHub Pages он есть) или localhost при разработке. Открытие файла напрямую и обычный HTTP-адрес компьютера в локальной сети для этого не подходят. Для публикации загружайте также манифест, worker и все иконки. PNG можно пересоздать командой `node tools/build-icons.cjs` при наличии Playwright и браузера.

## GitHub Pages

1. Создайте репозиторий и загрузите файлы. `index.html` должен быть в корне.
2. **Settings → Pages → Build and deployment → Deploy from a branch**.
3. Выберите ветку (обычно `main`) и **/(root)**, нажмите **Save**.
4. Откройте адрес сайта после публикации.

Используется публикация из ветки согласно [документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site). `.nojekyll` отключает обработку Jekyll. Отдельная сборка не нужна. Публикация на GitHub не выполнялась: в исходной папке нет Git-репозитория и remote.

В исходнике присутствуют личное имя, план и исходные анализы из ТЗ: они будут доступны посетителям опубликованного сайта. Локальные копии присланных исходников находятся в `backups/` и исключены из Git. Первый исходник переведён из Windows-1251 в UTF-8 без изменения содержимого; рабочий план сохраняет его веса, объём и разгрузки с уточнениями из ТЗ (без румынской тяги, ноги RIR 3, нейтральный хват, мост в тренажёре и работа на плечевой пояс).

При установленном Chrome можно задать `TEST_BROWSER_CHANNEL=chrome`. Тест сам поднимает локальный сервер и использует изолированные профили, не затрагивая пользовательский дневник. Проверяются 16 недель, SVG, даты ПКТ и дозы на границах недель, совместимость старых отметок, полноэкранные графики и масштабирование, миграция v4/v2, нулевые значения, безопасность патчей, восстановление архива, отказ буфера обмена и хранилища, повреждённые сохранения и мобильная ширина. Снимки интерфейса создаются в `test-results/`.
